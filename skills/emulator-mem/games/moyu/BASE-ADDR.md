## 1. 最终寻址方案 (v2, pd/pt 直连)

```
base_map.json = {
  seeds: { pd_host, pt_host },   # 游戏进程 页目录页/页表页 的宿主地址 (真实表页)
  pdi, pti,                      # 实体在 PD/PT 中的条目号
  heap_delta,                    # 游戏堆 物理→宿主 线性δ (锚点碰撞解出)
  page_off, role_id, pid
}
读取: PT[pti] → 叶子物理 φ → 宿主 = φ + heap_delta → +page_off → 结构体字段
字段: x@-0x284 y@-0x280 x2@+0xAC y2@+0xB0 (双槽互证) level@+0x21C role_id@0
```

- 用法: `python mysj_read.py [--watch|--resolve]`
- 定位: `python resolve.py` (全流程 ~5min: census 16s → δ求解 200s → PDPT索引 25s →
  遥测/实体锚点 → 堆δ反解 → 页表反查 → 种子链落盘)
- 稳态读取: 每次只读 2 次 (PT 条目 + 字段), <0.1s

## 2. 管线 (resolve.py)

1. **实例选择**: 多开按锚点探测 (RSS 启发式不可靠)
2. **PAE 引擎** (pae.py): census 表页 (门槛≥3) → δ 求解 (PD 条目互证,
   两段式探针+全局收编, ~200s) → 区域多数票块表 → 表页 phys↔host 对 → PDPT 索引
3. **锚点**: 遥测 JSON 收集全部 role_id (多角色都试) → 双槽互证找场景实体
4. **堆段 δ 反解**: 锚点宿主页 - φ ∈ PT目标空间, 软打分 (抗漂移), 命中率 85-97%
5. **页表反查**: φ→PT(倒排索引)→PD(内容扫描)→PDPT(内容扫描), 候选 + 种子回环验证
6. **交付**: 匹配候选的 (pd_host, pt_host, pdi, pti) + heap_delta 落盘

## 3. 关键认知 (踩坑沉淀)

1. guest = **32 位 PAE** (PTE hi32 ∈ {0, 0x80000000}); PDPT 仅 4 条目、32B 对齐
2. 宿主侧客户机 RAM **持续漂移** (区域整体滑动): δ 跨运行必失效,
   单次管线必须在同一稳定窗口内完成; 表页相对稳定, 堆页分钟级迁移
3. δ 互证只对 **PD 页**成立 (条目指向 PT=表页); PT 条目指向数据页, 不可互证
4. 真 PDPT 是稀疏结构 (4 条目), 混在内核数据页里; 用"连续 PD 对"签名识别
5. 物理掩码必须 **0x000FFFFFFFFFF000** (0xFFFF...F000 保留 NX 位 → 灾难)
6. 读取实体用 **页内偏移** (0xAA0); 页基地址减字段偏移会跑到前一页
7. 内核直 map 的 NX PTE 会污染一切 qword 扫描 → 用户半区过滤 hi32==0
8. nesec 对宿主侧 ReadProcessMemory 全程无感知 (零崩溃)
